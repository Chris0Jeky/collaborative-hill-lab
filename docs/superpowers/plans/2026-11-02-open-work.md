issues #92, #95 and #96, and repair reproducible defects found during review.

**Architecture:** Keep the deterministic engine and historical experiments
unchanged where possible. Add separately versioned research contracts and
separate experiment directories. Publish through the connected GitHub tools;
the uploaded source is reconciled against the live tree before editing.

**Tech stack:** Existing Python 3.12 package, exact fractions, pytest, Ruff,
strict mypy and the committed dependency lock.

**Specs:** Issues #92, #95 and #96; each research slice adds a design and
hand-derived predictions before its first execution.

## Constraints and review focus

- Preserve historical study inputs and all existing experimental evidence bytes.
- No provider calls, study freezes, final weights or changes to human-owned decisions.
- A failed or interrupted run must not acquire fabricated spend or outcome data.
- Policies see observations only; model truth is confined to the environment and scoring.
- Branch histories and labels must be validated without following parent paths.
- Report negative and null results, explicit model assumptions and incomplete integration.
- Local checks supplement exact published-head Ubuntu and Windows CI.

## Verification sequence

For each behavioral fix, observe the regression fail before changing production
code, then run its focused suite and lint/type checks. Research designs are
committed before execution. After review corrections, rerun relevant checks on
the new head. Before merging, the full existing gate and any new regeneration
gates must pass on the exact published commit. Check the final integration tree
and preserve local execution versus hosted-CI provenance in the handoff.
